# Settlement Identity Design v7 — Section-9 Fixture Inventory

This inventory maps every mandatory acceptance scenario, variant, and control from Explicit Settlement Identity Design v7 (§9, lines 391–468) and Round 8 Common Rules (part 8) to its owning round (`8a`–`8f`), production entry points, numeric and structural assertions, and any external harness required.

**Activation rule:** Each round writes and activates only its own fixture groups alongside its implementation. Deferred groups (`8b`–`8f`) are not added to the default pgTAP suite in `8a` and are not counted as passing or failing-before in `8a`.

**Common physical and settlement assertions (every active §9 fixture):**

- Physical fields present at `30a9c74`: `movement_type`, `quantity`, `total_cost`, `unit_cost`, `occurred_at`, `adjusts_movement_id`, `cover_inflow_movement_id`, `cover_deficit_movement_id`, `closed_bucket`, and pinned `shift_id` / `movement_attributions.shift_id` where applicable.
- Explicit settlement facts: `app.accounting_piece_keys`, `app.deficit_settlements` (`settlement_kind`, `settled_qty`, `provisional_value`, `inflow_value`, `required_bucket`, `carrier_shift_resolved`, `carrier_shift_id`), `app.deficit_settlement_effects` (`posted_b`, `posted_c`), `app.deficit_settlement_events` + `app.deficit_settlement_event_deltas` (exact class and locus), `app.dependent_operation_heads`, `app.stock_movements` posting links and `dependent_mode`, and `app.reversal_settlement_splits`.
- Replay visitation via privileged probe (`app.replay_read_probe`):
  - Forced-full runs assert `selected_cuts` has `checkpoint_id = null` for all items and `processed_pieces` contains the named full piece sequence.
  - Resumed runs assert the exact `checkpoint_id` in `selected_cuts` and the exact named suffix in `processed_pieces` (with prefix pieces absent).
  - Selection tests leave the override off (`override_mode = 'none'`) and assert the exact cut chosen by the production selector.
